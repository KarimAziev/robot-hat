# AS5048A magnetic encoder

`robot_hat` supports the SPI/PWM **AS5048A** as both an absolute angular
position sensor and a signed cumulative encoder. The similarly named AS5048B
uses I²C and is not handled by this driver.

The normal API uses SPI because it provides parity and protocol-error checking
as well as magnetic diagnostics. PWM capture and daisy-chain mode are not
currently implemented. OTP zero-position programming is intentionally absent:
an accidental burn is permanent. Use `zero_offset_degrees` for a reversible
software zero.

## Identify and electrically verify the module

The supplied board photos show these labels:

- SPI header: `GND`, `CSN`, `CLK`, `MOSI`, `MISO`, `+5V`, `GND`, `GND`
- PWM header: `GND`, `+5V`, `PWM`

Use the printing on the actual board as the authority; marketplace descriptions
often combine AS5048A and AS5048B specifications and may contain impossible
voltage or size values.

The photographed module exposes a `+5V` input and appears to contain additional
power circuitry, but a photo is not enough to prove its logic voltage or level
shifting. Before connecting it to a Raspberry Pi:

1. Obtain the seller's schematic, or power only the module and measure the
   idle/high voltage on `MISO` and `PWM` relative to `GND`.
2. Do not connect a signal above 3.3 V to a Raspberry Pi GPIO.
3. If a high signal can approach 5 V, add proper level shifting. Also confirm
   that 3.3 V `CSN`, `CLK`, and `MOSI` levels satisfy the powered module's input
   thresholds.
4. Share ground between the module, Raspberry Pi, and motor electronics. Keep
   encoder wiring away from motor and high-current PWM wiring.

The check is necessary because the bare chip's digital levels follow its supply
configuration, while breakout boards can add regulators or translators in
different ways.

## Raspberry Pi SPI wiring

After logic-level compatibility is verified, a typical SPI0/CE0 connection is:

| Module | Raspberry Pi signal                          | BCM GPIO |     Physical pin |
| ------ | -------------------------------------------- | -------: | ---------------: |
| `GND`  | Ground                                       |        — | 6 or another GND |
| `CSN`  | SPI0 CE0                                     |    GPIO8 |               24 |
| `CLK`  | SPI0 SCLK                                    |   GPIO11 |               23 |
| `MOSI` | SPI0 MOSI                                    |   GPIO10 |               19 |
| `MISO` | SPI0 MISO                                    |    GPIO9 |               21 |
| `+5V`  | 5 V, only if required by the verified module |        — |           2 or 4 |

With `CSN` on CE1, use GPIO7/physical pin 26 and `device=1`. Enable SPI in
Raspberry Pi configuration first. Linux should then expose `/dev/spidev0.0` or
`/dev/spidev0.1`.

Install the optional Linux SPI backend on the target:

```bash
python -m pip install "robot-hat[spi]>=3.0.0,<4"
```

The package import remains hardware-independent; `spidev` is loaded only when
a `SpidevDevice` is constructed.

On macOS and other non-Raspberry-Pi development hosts, call
`setup_env_vars()` before constructing hardware. It sets
`ROBOT_HAT_MOCK_SPI=1`; default AS5048A constructors then own a
`MockAS5048ASPI` instead of importing `spidev` or opening a Linux device. The
mock reports a healthy stationary sensor by default.

## Read absolute angle and diagnostics

```python
from robot_hat import AS5048A

with AS5048A(bus=0, device=0) as sensor:
    diagnostics = sensor.read_diagnostics()
    if not diagnostics.data_valid:
        raise RuntimeError(f"AS5048A magnetic setup is invalid: {diagnostics}")

    print(sensor.read_raw_angle())  # 0..16383
    print(sensor.read_angle_degrees())  # 0 <= angle < 360
    print(sensor.read_magnitude())
```

The Linux adapter configures SPI mode 1, 8-bit words, and a conservative 1 MHz
clock. `max_speed_hz` may be increased but is rejected above the datasheet's
10 MHz limit.

`read_diagnostics()` reports offset-compensation completion (`OCF`), CORDIC
overflow (`COF`), field too strong (`COMP low` in the datasheet), field too weak
(`COMP high`), and automatic gain control. CORDIC overflow makes angle and
magnitude invalid.

Every register read verifies response parity. If the sensor sets its SPI error
flag, the driver reads and clears `ERRFL`, then raises `AS5048AProtocolError`
with typed framing, invalid-command, and command-parity flags.

## Use it as a cumulative encoder

```python
from robot_hat import AS5048AEncoder

with AS5048AEncoder(
    bus=0,
    device=0,
    max_abs_speed_rps=5.0,
) as encoder:
    sample = encoder.read_sample()
    print(sample.ticks, sample.timestamp_monotonic_ns)
    print(encoder.read_health())
```

The encoder provides 16,384 ticks per revolution and unwraps successive
absolute positions into a signed cumulative counter. Like every single-turn
absolute encoder, it cannot infer the correct number of turns if the shaft can
move half a revolution or more between samples. Set `max_abs_speed_rps` to a
real upper bound and sample faster than its derived limit. A scheduling gap or
an exact half-turn transition is rejected and re-baselined rather than reported
as invented motion.

Use `invert_direction=True` to reverse the cumulative sign. `reset(ticks)`
changes only the software counter.

## Use it as an absolute position sensor

```python
from robot_hat import AS5048AAngularPosition

with AS5048AAngularPosition(
    bus=0,
    device=0,
    zero_offset_degrees=17.25,
) as position:
    print(position.read_angle())
```

The software zero is reversible and leaves the chip's OTP memory untouched.

## Dependency injection and ownership

Tests and non-Linux backends can inject `SPIABC`. An injected SPI device is
caller-owned and is not closed by `AS5048A`. Likewise, a high-level wrapper
does not close an injected `AS5048ASensor`:

```python
sensor = AS5048A(spi=my_spi_device)
encoder = AS5048AEncoder(sensor=sensor)

try:
    encoder.initialize()
    sample = encoder.read_sample()
finally:
    encoder.close()  # leaves sensor and my_spi_device open
    sensor.close()  # leaves the injected my_spi_device open
    my_spi_device.close()
```

Do not pass both `sensor` and `spi` to one high-level wrapper; their ownership
and configuration would be ambiguous.

For protocol-aware local development, inject the reusable mock explicitly:

```python
from robot_hat import AS5048AEncoder, MockAS5048ASPI

mock_spi = MockAS5048ASPI(angle_counts=1000)
encoder = AS5048AEncoder(spi=mock_spi)
encoder.initialize()

mock_spi.advance(120)
print(encoder.read_sample())
mock_spi.set_diagnostics(magnet_too_weak=True)
print(encoder.read_health())

encoder.close()
mock_spi.close()
```

`MockSPI` is also available for generic SPI protocol tests that need queued raw
responses. `MockEncoder` is the lighter choice when an application only needs
to exercise `EncoderABC` and does not need AS5048A register behavior.

## Hardware validation status

The driver has deterministic tests for framing, parity, pipelined reads,
diagnostics, error clearing, ownership, unwrapping, and ambiguous transitions.
These are not evidence from the specific module, magnet, wiring, alignment, and
target host.

Before relying on it for closed-loop motion, record at least:

- measured logic levels and supply voltage;
- stable diagnostics over a full mechanical revolution;
- angle continuity across 0/360 degrees in both directions;
- observed maximum sampling gap at maximum shaft speed;
- behavior with the magnet intentionally too far away and too close;
- repeatability after power cycles and under motor electrical noise.
